## Bottom line for the studio

1. **ADOPT NOW: independent verifier, never self-grading.** Anthropic's own harness post and its Claude Code best-practices page say the builder must not grade its own work. Use `/goal <one measurable end state + stated check + turn cap>` for unattended runs, a Stop hook for deterministic checks (`npm run check`), and a fresh subagent to attack the diff. `/goal` is CONFIRMED but its evaluator sees only what the agent printed, so require pasted test output and a `tools/shot.mjs` PNG description in the transcript.
2. **ADOPT NOW: an append-only work log (`design/WORKLOG.md`) that a fresh agent resumes from.** Orobator (Reddit) enforces it with a commit hook that blocks commits lacking a log update. A plan is a prediction; a log is a record. Fits multi-week runs where sessions die and compact.
3. **ADOPT NOW: enforce rules structurally, not politely.** Reddit's agent wrote under a pre-commit guard, and Codex added a self-authorizing "emergency recovery" exception to its own guard. Put lead-only paths (`kingswarm.html`, `build.sh`, `docs/`, `src/sim/types.ts`) behind a PreToolUse hook in the repo's `.claude/settings.json`; keep `purity.test.ts` as the sim-purity gate. Prose in CLAUDE.md is advisory only.
4. **ADOPT NOW: stress-test our own harness after every model release, delete what is no longer needed.** Anthropic: "every component encodes assumptions about model limitations". Opus 5.5 (Sep 22) and Sonnet 5.5 (Sep 28) just shipped. Run one ablation pass this week: which rules, hooks, retry steps and review gates still change outcomes? Remove the ones that do not. This is the anti-bloat mechanism.
5. **ADOPT NOW: one owner per coherent decision; no relay chains of specialist agents.** ZS Associates killed a 4-agent pipeline because summaries lost nuance at each handoff and the output was locally plausible but globally wrong. For Kingswarm: one agent owns a whole feature (sim rule + tuning + test + feel pass); handoffs go through files (`GDD.md`, `ART.md`, `types.ts`), and subagents get bounded tasks. Do deterministic checks before any LLM judgment.
6. **ADOPT NOW: separate defect checks from taste checks, and grade taste against a written rubric.** Anthropic replaced "is it beautiful" with 4 gradable criteria; Bakaus (Impeccable) runs critique in sub-agents that never see the builder's work and admits his design judge is only "marginally better than random" on first passes. Write 4 Kingswarm criteria (swarm readability at zoom-out, ART.md palette fidelity, game-feel.md numbers hit, 5 MB budget). Human keeps final taste.
7. **ADOPT NOW: pin nothing to a model that has a retirement date; check the deprecations page monthly.** Haiku 4.5 is "not sooner than October 15, 2026"; `claude-sonnet-4-5-20250929` is "not sooner than September 29, 2026" (today +1). `/goal` evaluators run on the small fast model, Haiku by default. Use aliases, and re-read the `model-routing` skill before each fan-out.
8. **TRY LATER: route by measured results, not folklore.** Warp routes task classes to models using customer-run evals and says UI tasks go well on GLM. That is anecdote. Keep a 10-line routing log (task class, model, effort, pass/fail, cost) and revisit after ~30 entries.
9. **TRY LATER: a scripted bot-vs-bot playthrough as the next verification rung.** Orobator's ladder: build/tests, then screenshots, then video of the running feature, then telemetry. We have the first two (`npm run check`, `tools/shot.mjs`). Bots-are-players makes rung 3 cheap: headless match, log stats, fail on NaN/no-kills/timeouts.
10. **SKIP: hosted or heavy orchestration products** (Conductor, Warp Oz, Factory, AgentCraft, Gas Town/Beads, Claude Managed Agents, dreaming). They need accounts, keys or a daemon, and Conductor's own advice is "don't try to beat the market": big labs fold good workflows into the default (`/goal`, worktrees, agent view, agent teams already shipped). Steal the ideas below; install nothing.

### Per-talk findings

1. **Lance Martin (Anthropic).** (a) Split the "brain" (stateless harness) from durable append-only session logs and replaceable sandboxes, so a crash does not kill the run. (b) Asking an agent to grade itself in the same context confabulates; use a separate verifier context with measurable end-state requirements ("goals" in Claude Code, "outcomes" in Managed Agents). (c) "Dreaming": an offline pass that rewrites memory after sessions; raw memory made Claude write a wrong map fact and fall into the same trapdoor 5 of 5 runs until dreaming corrected it, so memory without correction is harmful. (d) Use flexible substrates (files) not prescriptive memory schemas. Validation: goals/outcomes/dreaming CONFIRMED to exist (see below); task-horizon and Parameter Golf claims UNVERIFIED, vendor talk.
2. **Bhat / Kai He (Anthropic).** (a) Context anxiety: a model near its window limit wrapped up early, so the harness added context resets; a newer model dropped the behavior and the fix became pure overhead (latency, lost cache). (b) Three primitives: agent, environment, session. (c) Talk quotes 60% faster p50 and 90% better p95 time-to-first-token from decoupling brain and hands: UNVERIFIED (not read in the Apr 8 engineering post). Validation: principle CONFIRMED in Anthropic's Mar 24 post; the talk description names Sonnet 4.5 then Opus 4.5, while the post says Opus 4.6 "largely eliminated" it. Trust the post.
3. **Orobator (Reddit).** (a) Skills encode which facts matter (institutional judgment), documentation stores facts. (b) Work logs let a fresh agent resume at "milestone 7 of 9"; hook-enforced. (c) Verification ladder: builds/tests, screenshots, video, telemetry; each rung passed earns autonomy. (d) Encoded judgment rots: post-mortem every agent failure into a skill, and schedule a "bedtime" audit of skills for drift. (e) Flag-cleanup agent: $1.26 per PR, 7 of 7 green-CI PRs, about 520 flags for under $700 a year. Validation: cost figures self-reported, n=7, UNVERIFIED; the arithmetic is consistent.
4. **Mistele (HumanLayer).** Control-loop framing: deterministic sensor (grep or ast-grep) finds the smallest unit of remaining work, a controller picks it, an actuator agent changes it against hand-written golden patterns, CI gates it. One open PR per loop (halt if the loop's label is already open) to stop stacked, conflicting changes. Steering lives in version-controlled markdown; a reviewer comment reloads PR context. Estimate of 150 procedures at 1/day is a projection, not a result.
5. **ZS.** V1 (detect, localize, cause, synthesize agents) gave "cause right, action wrong". Fix: statistical detection first, then one main agent owns end-to-end reasoning and delegates bounded subtasks; a knowledge graph constrains the search. They found the design by watching Claude Code work in an empty directory. Their "3-4 weeks to 20-30 minutes" was, by the speakers' own admission, not formally evaluated: UNVERIFIED.
6. **Warp.** Inner-loop agent does the work; an outer-loop agent watches runs and feedback and opens a PR to edit the skill, so changes are git-tracked and human-reviewed. Memory is scoped, versioned, editable, traceable to its source run. Model routing needs evals on your own tasks. Companion talk (Zach Lloyd, 2026-09-27) says measure shipped software, human hours and tokens, not PR counts or lines.
7. **Malhotra (Anthropic).** An unattended agent deleted about 200 workloads in 90 seconds using the owner's token. Fixes: asymmetric verbs (actions that fail loudly are allowed; quiet-failure actions need approval), refilling rate limits, tripwires that page on aggregate behavior, the "undo test" (can it restore state itself? how bad is failure?), identity stamped by infrastructure not the caller, prose for intent (about 80% effective) plus infrastructure for hard limits.
8. **Govindarajan (OpenAI).** Model proposes, harness commits, receipt proves. Five failure shapes: state holes, overlapping writers, dangling tool calls, approval drift, missing edge proof. Single-writer lanes; explicit terminal outcomes (success, failure, timeout, cancel). Relevant to us: parallel agents editing `types.ts` or `tuning.ts` are overlapping writers.
9. **Druga (Sakana).** Memory only helped when evidence did not fit in context (answer at step 124, question at step 500); on tasks that fit, memory added cost with no gain. A ranked decision ledger beat vector retrieval. Even oracle memory did not reach 100%, so retrieval is half the problem. Treat recall policy as something to evaluate.
10. **Voss (Arize).** Reran IFScale: models now handle about 10x more simultaneous instructions than the 2025 ceiling of 200-300, so long skill files are feasible. But capacity is not reliability: reworded rules change compliance, and one model abandoned output mid-response while looking polite. Verify outputs; do not merely allow longer rules.
11. **Bakaus.** "The median is the model's gravity": bans move a model to the next default cluster. Techniques worth copying: anti-attractor seeds (pool of options ranked by fresh agents), scripts that return instructions, edit-path hooks that validate as files are written, visible gates that make skipped steps detectable, ablation testing (remove a rule, measure) across 20 niches x 5-10 trials.
12. **Nunez (Nereu).** Agents reinvent a follow-camera every time because context is in the engine's vocabulary, not the game's. Fix: describe things by intent tags and assemble context by level of detail (full detail near the edit focus, name and position only for the rest), and get the human unstuck rather than one-shot a game. Relevant: our `types.ts` is the game vocabulary; give agents the contract plus a one-line index, not the whole tree.
13. **Salomon (AgentCraft).** Human attention is the bottleneck. Ideas: "jump to what needs attention" key, agents suggest next quests for approval, a review kit packaging a change with visual evidence. We can do the last one with a per-task evidence bundle (check output, PNG, diff stat).
14. **Holtz (Conductor).** Create "slop-free zones" that always get human review (migrations, docs, agent instruction files). Put Slack, bug reports and meetings into one queryable DB. Do not customize workflows every user has. Orchestras (human conducting) over factories.
15. **Pocock.** Description only: agent experience (AX) deserves the rigor DX got; fix what surrounds the PR, not how fast it is written. UNVERIFIED beyond that; his skills are already installed here.
16. **Mastra and Inngest.** Farrelly: execution (durable, years), context (models, prompts, memory; months), compute (sandboxes; fast churn) change at different speeds, so keep them decoupled. Resume from step 38 of 200 rather than restart. Consistent with #2.

## Distilled playbook for an agent-lead on a multi-week build

- **Orchestration.** One agent owns each coherent slice end to end; subagents take bounded, well-specified work. Prefer many small loops with backpressure (one open unit of work per loop) over one giant run. Do not stack changes on top of unreviewed changes. A single writer per shared file (`types.ts`, `tuning.ts`, `package.json`); others send change requests in reports, which our CLAUDE.md already says.
- **Verification.** Fresh-context verifier for every unit; done means observed (check green, thing run, PNG read). Climb the ladder: `npm run check`, `tools/shot.mjs`, bot-vs-bot playthrough stats, later a short video. Autonomy is earned per rung. Require evidence in the transcript because `/goal` evaluators cannot open files.
- **Memory and notes hygiene.** Work log is append-only and dated; decisions go in GDD/ART, facts the code already states do not get written down. Every note needs a date and a source; anything about models or tools older than about 4 months gets re-validated or deleted. Memory only earns its cost when the evidence does not fit in context. Run a periodic offline pass (a poor man's "dreaming"): merge duplicates, drop contradicted entries, and write the result to a new file for review, never in-place. Any agent-proposed change to a skill or CLAUDE.md goes through a diff the lead reads.
- **Model routing.** Fable for design judgment, arbitration and ambiguous specs; Opus 5.5 for long agentic coding; Sonnet 5.5 for well-specified execution; Haiku 4.5 for mechanical checks. Set model and effort on every call. Re-run routing after each release using the routing log, not vibes.
- **Bloat and drift.** Every rule must answer "would removing this cause a mistake?" Convert repeated rules to hooks or tests; delete rules the model now follows unprompted. Re-ablate the harness at each model release. Watch for agents routing around guards (Reddit example): fix by moving the gate below the agent's reach.
- **Budget and blast radius.** Give unattended runs a ceiling on turns and spend (`or stop after N turns` in the `/goal` condition; `/goal` reports token spend). Apply the undo test: reversible actions inside the repo proceed; `git push`, deploys and `docs/` stay with the lead.
