# Next brief (not yet launched): integration into a playable game

Launch only after the interrupted stages in `design/WORKLOG.md` (save point 2026-09-30) are resumed and finished, so every layer's API is final. One owner (Opus, high effort) for the whole feature; an independent verifier after; at most 2 other build tracks running at the same time.

Owner files: `index.html`, `src/main.ts`, `src/app/**`, `src/input/**`, `e2e/**`. May add a small `src/render/portrait.ts` if the renderer does not already expose King portraits.

1. **Input (`src/input`)** → `PlayerInput` per tick. Keyboard by `event.code` (WASD/arrows move, Shift or Space dash, Q ability, E ultimate, F recall, P/Esc pause), mouse (aim through `renderer.screenToWorld`, LMB hold to fire or toggle mode from settings, RMB recall, pointer capture so firing survives the cursor leaving the canvas, no context menu, no Space scrolling, release everything on blur). Gamepad standard mapping (LS move, RS aim, RT fire, LB/B recall, A dash, X ability, Y ultimate, Start pause; aim assist on; menus through `ui.nav`). Last-used device drives `ui.setDevice`. Touch comes in M3.
2. **Loop (`src/app/loop.ts`)**: fixed 60 Hz accumulator (clamp 0.25 s), render with interpolation alpha, pause, time scale for the match-end slow-mo, auto-pause when the tab is hidden in solo play.
3. **Battle (`src/app/battle.ts`)**: `createWorld(config)` from `game.battleSetup`, rival bot from `src/ai` (profile id + level), per step: inputs → `step` → `facts.observe` → `renderer.onEvents` → `audio.onEvents` → HUD frame, bot signals (tells, barks) → renderer/HUD; end detection → result.
4. **App state machine (`src/app/app.ts`)** on top of `src/game` (profile, run): first launch = one Play button → guided battle 1; returning = title (Continue run / New run / Codex / Settings) → hero pick → rival card → battle → result → draft → … → run won / run over. Pause, settings (persisted through the profile), codex, how-to. Title background = live bot-vs-bot attract battle. Portrait phones show a "rotate your device" card.
5. **FTUE hints (`src/app/hints.ts`)**: the adaptive prompts from `design/research/onboarding-ux.md` §1 (move, hold to fire, recall, dash, ability), each at most 8 words, shown once per profile, never pausing the sim.
6. **Debug and test hook** `window.__ks`: `state()`, `advance(seconds)` (step the sim without waiting for real time), `setAutoplay(profileId | null)` (a bot plays the human side), `winBattle()` / `loseBattle()`, `resetProfile()`; URL params `?test`, `?seed=`, `?autoplay=expert`.
7. **E2E (Playwright, system Chromium with the GPU flags in `playwright.config.ts`)**: boot → Play → battle starts within 10 s; autoplay wins battle 1; draft appears; pick; battle 2 starts; pause/resume; settings persist across reload; Continue run works after reload; no console errors; average frame time in a full fight under 8 ms. Screenshots of each step to `shots/e2e-*.png`, looked at.
8. **Build**: `npm run build` to `dist/` with relative base; music lazy-loaded; report total and initial bytes against the 5 MB / 8 MB budget.

Then the M1 gate: lead reviews e2e screenshots and frame sequences, bot metrics against GDD §3.4, and two fresh-eyes critics (first-time player, art director) with the four-point rubric: swarm readability when zoomed out, ART.md palette fidelity, game-feel.md numbers, size budget.
